# 上架华为应用市场（AppGallery）工作清单

> 编制日期：2026-10-06 ｜ 对象：血压助手 v1.0.0（HarmonyOS NEXT / API 12 单机应用）
> 依据：华为官方文档《APP核准(APP备案)指引》《HarmonyOS应用备案指导和常见问题》、华为开发者联盟论坛《鸿蒙原生应用上架流程相关问题》，以及 2026 年公开上架实践资料。

---

## 0. 先看两个结论（它们决定了工作量量级）

### ✅ 好消息：本项目**无需 APP 备案**

官方《APP核准(APP备案)指引》明确规定，单机应用可选择「**您的 APP 为单机 APP**」而**无需核准（备案）**：

> **单机应用定义**：未通过连接公共互联网提供互联网信息服务的移动应用程序。

本项目 `module.json5` 中**不存在任何网络权限**（NFR-5 零网络权限设计），无服务器、无账号体系、数据全部存储在本机 SQLite —— **完全落在"单机应用"定义内**。

**这意味着省掉了整个 APP 备案流程**：接入商初审 3–5 个工作日 + 工信部终审 2–20 个工作日（合计约 5–25 个工作日），以及备案所需的域名、服务器、主体证件核验等一整套材料。

> 注意：备案表里必须**如实勾选**「您的 APP 为单机 APP」，不要误选"服务器在中国大陆"。如果将来二期加了云端同步，就**必须**补办备案。

### ⚠️ 风险点：**类目归属**是最大的不确定性

华为对「医疗健康」类目要求行业资质（论坛《鸿蒙原生应用上架流程相关问题》原文：

> 医疗类：医疗机构执业许可证、互联网药品信息服务资格证书等

同时有资料指出医疗健康属**敏感类目**，可能需要 **CMA/CNAS 第三方测试报告**（覆盖功能、性能、安全、兼容性、功耗，出具时间须在 6 个月内）。

**本项目的定位辩护**（提交审核与填写类目时应按此表述）：

| 我们不做什么 | 依据 |
|---|---|
| 不提供诊断结论 | 所有提示均带「仅供参考，不构成医疗诊断」声明 |
| 不提供用药建议 | 用药界面固定展示「请严格遵医嘱服药，本 App 不提供用药建议」 |
| 不连接医疗设备 | 无蓝牙、无 Health Kit、手动录入 |
| 不采集/上传任何个人数据 | 零网络权限，数据仅存本机 |
| 不做在线问诊/处方/售药 | 无相关功能 |

**建议类目**：选「**健康**」或「**运动健康**」，**不要**主动选「医疗」。
但审核方可能从严判定 —— 这是本项目最可能被驳回的地方，需预留一轮沟通时间。

> **务必做的一件事**：在应用内显著位置（关于页 + 首启）明确声明「**本应用不是医疗器械，不用于疾病诊断或治疗**」。这一条既符合合规要求，也是类目辩护的关键材料。

**隐私政策必须包含**（华为审核机器 + 人工双检，命中关键词即驳回）：
- 收集的个人信息类型、目的、方式、范围（本项目可如实写「**不收集任何个人信息**」）
- 权限使用说明（逐条对应实际功能）
- 数据存储位置与期限（本机存储、不对外传输）
- 数据删除方式（设置页「清空所有数据」）
- 联系方式

> 本项目在隐私合规上**极其干净**：零网络权限、无账号、无第三方 SDK、无数据上传。如实写即可，不需要编造。这是单机应用的天然优势。

## 5. 本项目的上架优势（如实登记）

这些设计决定在实现时就做了，**直接减少了上架工作量**：

| 已有设计 | 上架收益 |
|---|---|
| **零网络权限**（`module.json5` 无 INTERNET） | 免 APP 备案；隐私合规极简；不触发数据出境/传输审查 |

| **已有免责声明体系** | 三处免责文案已资源化（`disclaimer_bp` / `disclaimer_med` / `disclaimer_full`），补充「非医疗器械」即可 |
| **目标 API 12** | 满足 ≥10 的门槛要求 |
| **Stage 模型 + 非免安装** | 符合包格式要求 |
| **`app.json5` 不含 `debug` 字段** | 满足"包内不可含调试信息"要求 |
