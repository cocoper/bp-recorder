# 隔离验收流程（安全验收卡）

> 依据：《全面审查报告与修改要求-2026-10-11.md》R20.1 / R20.2 / R20.4 与第 2 节强制规则 4。
> 一句话：**任何可能破坏数据的验收，都不许在用户现用安装上做**；本文给出可以做的地方和做法。

## 0.5 测试包名变体与静态门禁（审查 R20.1）

```bash
node tools/check-isolation.mjs                                  # 静态不变量：必须全绿
node tools/device-batch.mjs --dry-run                           # 核对真机批将执行的命令（离线）
node tools/make-audit-variant.mjs --status                      # 看当前包名
node tools/make-audit-variant.mjs --apply                       # 切到 com.bp.recorder.audit
# …在隔离实例上跑破坏性验收（照 docs/验收卡模板.md 填记录）…
node tools/make-audit-variant.mjs --restore                     # 一定切回生产包名
```

- 审计变体的应用数据目录与生产安装**完全分开**（不同 bundleName），卸载/清空只影响变体。
- `--apply` 会拒绝在 app.json5 有未提交改动时执行，避免把变体包名混进提交。
- 真机隔离必须由**验收卡 + 前后哨兵快照**证明，静态门禁不代替它。

## 1. 硬规则

1. 用户现用安装（包名 `com.bp.recorder`）**只允许**：启动、浏览、录入/编辑/打卡（用户自己会做的操作）、只读取证（`hdc file recv` 拉库、`snapshot_display` 截图）。
2. **禁止**在其上：卸载/重装、清空所有数据、批量导入测试数据、注入故障、修改数据库文件、做性能压测。
3. 「先导出 CSV」**不是**安全前提：R08–R10 已证明三份 CSV 有损（丢秒毫秒、用药打卡丢日期、同名药品身份冲突）。
4. 任何测试数据必须能一眼识别为合成数据（药名/备注带 `测试` 前缀或独立命名空间），不得与真实记录混用命名。

## 2. 三档隔离路径

| 档 | 做法 | 适用 | 现状 |
|---|---|---|---|
| ① 独立设备/模拟器 | 在另一台设备或模拟器上装普通构建（`entry-default-signed.hap`），数据沙箱天然隔离 | 卸载重装、授权弹窗、锁屏送达、性能压测 | **可用（首选）** |
| ② 同机测试包名 | 把 `BpRecorder/AppScope/app.json5` 的 `bundleName` 临时改为 `com.bp.recorder.test`（或加一个 `product=test` 变体）后构建安装；它是**独立应用**，有独立沙箱与数据库；验收完卸载测试包并 `git checkout` 还原 | 只有一台设备时做破坏性验收 | **待实现**（已登记为 R20 待办，见 §5） |
| ③ 仅库/服务隔离（自动化） | Hypium 测试用独立库名 + 独立实例（R17），或 parity 内存桩（`docs/review-2026-10-11/repro.cjs`）；不涉及真机破坏性步骤 | 逻辑、事务、导入导出、迁移 | 部分可用：内存桩可用；独立库实例随 R17 落地 |

## 3. 破坏性验收的标准流程（以档 ①/② 为例）

1. **前置**：确认目标设备上没有用户真实数据（新装/模拟器），或已用档 ② 的独立包名。
2. **哨兵快照**（R20.4）：验收前后各取一次，证明「非测试数据未变」：
   - 源码指纹：`docs/review-2026-10-11/source-manifest.json` 的生成方式（对 `BpRecorder/entry/src/main/ets/**/*.ets` 求 SHA-256）；
   - 生产侧（真机档 ② 才需要）：用户包 `com.bp.recorder` 的记录计数与库文件哈希，验收前后逐项比对。
3. **执行**：按验收卡跑；合成数据只进测试包/测试库。
4. **取证**：记录设备型号、系统/API 版本、包名、应用版本、开始结束时间；截图**不得包含真实健康记录**。
5. **收尾**：卸载测试包、清理临时数据；把结论写进 `docs/审查整改执行记录.md`。

## 4. 记录项（报告 §5.3 真机门禁要求）

| 项 | 必须记录的内容 |
|---|---|
| 环境 | 设备型号 / 系统版本 / API / 包名（区分生产与测试）/ 应用版本 / 时间 |
| 通知 | 允许与拒绝两条路径、锁屏、杀进程、系统拒收的**错误码与请求类别** |
| UI | 录入/编辑/打卡/历史查询；深浅色、字体放大、屏幕阅读器、横竖屏 |
| 输出 | 相册、接收端分享、完整长图、打印/PDF（「面板打开了」不等于内容有效） |
| 性能 | 4000 条血压 + 1100 条合成用药日志下的冷启动、保存延迟、滚动；必须写测量方法与样本数 |
