## 1. 项目概述

### 1.1 产品定位

一款运行在**华为鸿蒙手机（HarmonyOS NEXT，API 12+）**上的**个人单机版**血压记录、智能分析、用药管理与周期报告应用。数据完全存储在本机，无服务器、无账号体系、无网络依赖。

### 1.2 目标用户与场景

- 单一用户（本人），日常居家自测血压（电子血压计手动读数，App 不负责蓝牙采集）。
- 典型场景：晨起/睡前测量后快速录入 → 查看近 7 天/30 天趋势 → 发现异常时收到分级提示 → 就医前导出数据给医生。
- 用药场景：按医嘱设定服药计划 → 到点系统提醒 → 一键打卡 → 统计服药依从率并与血压趋势对照。
- 报告场景：每周/每月生成周期报告 → 保存长图或 PDF → 微信发给家人或打印给医生；血压趋势图一键分享。
- 迁移场景：就医获得历史数据或换机时，通过 CSV 导入血压与打卡记录。

### 1.3 设计原则

1. **录入快**：从打开 App 到完成一条记录 ≤ 3 次点击（「+」→ 数字输入 →「保存」）+ 数字输入，该项在 CL-2 中作为可验收条目。
2. **本地优先**：所有数据存于本地关系型数据库，断网全功能可用。
3. **可上架标准**：虽暂不上架，但代码结构、权限声明、隐私合规按华为应用市场审核标准执行，避免后期返工。
4. **医学严谨**：血压分级与提示文案严格依据《中国高血压防治指南（2024 年修订版）》及家庭自测血压共识，所有提示附"仅供参考，不构成医疗诊断"声明。

### 1.4 明确不做（Out of Scope）

| 不做项 | 说明 |
|---|---|
| 蓝牙/设备直连自动采集 | 本期手动录入，数据模型预留 `source` 字段便于二期扩展 |
| 云端同步 / 多设备 | 单机版 |
| 多用户/家庭档案 | 单人使用，数据模型预留 `user_id` 字段 |
| 药品库存管理、处方拍照识别 | 用药只做计划与打卡，不做库存计数与 OCR |
| 三方分享 SDK（微信/QQ 直连） | 分享统一走系统分享面板，保持零网络权限原则 |
| 报告在线生成 PDF（应用内直接出 PDF 文件） | 鸿蒙无轻量本地 PDF 生成 API，PDF 走系统打印界面"另存为 PDF" |
| 上架应用市场 | 按可上架标准开发，但仅真机安装 |

## 2. 需求规格

### 2.1 功能需求（FR）

**FR-1 血压记录录入**
- FR-1.1 录入字段：收缩压（mmHg，整数 40–300）、舒张压（mmHg，整数 30–200）、心率（bpm，整数 30–220，可留空）、测量时间（默认当前时间，可修改）、时段标签（晨起/上午/下午/睡前/其他，默认按时间自动推断）、备注（可选，≤100 字）。
- FR-1.2 校验：收缩压必须大于舒张压；越界值拒绝录入并提示；**测量时间不得晚于当前时间**（防止误选未来日期污染统计口径；时间选择器上限为今天）。
- FR-1.3 支持编辑与删除已存记录（删除需二次确认）。

**FR-2 记录列表（首页）**
- FR-2.1 按时间倒序展示，每条显示：日期时间、收缩压/舒张压、心率、时段标签、分级色标。
- FR-2.2 分级色标：正常=绿、正常高值=黄、1 级高血压=橙、2 级及以上=红。**分级固定按 3.2-A 诊室血压表判定，不随任何设置变化。**
- FR-2.3 支持上拉分页加载（每页 20 条）。下拉手势保留（触发列表重算与视觉反馈），但本机为本地库、无远端数据可刷，**不作为验收项**。

**FR-3 趋势图表**
- FR-3.1 折线图：收缩压、舒张压、心率三条曲线，支持 7 天 / 30 天 / 90 天切换。
- FR-3.2 图上叠加参考线：140/90 mmHg（诊室血压）与 135/85 mmHg（家庭自测界值）。两条线**恒定同时绘制**；设置项「参考口径」（FR-7.1）只决定哪一条以**主参考线**样式突出显示，不改变分级。
- FR-3.3 单日多次测量时取该日平均值绘图。

**FR-4 统计分析**
- FR-4.1 周期统计（7/30/90 天）：平均值、最高值、最低值、标准差、测量次数。
- FR-4.2 分布统计：各血压分级区间的记录占比（如正常 60%、正常高值 25%……）。
- FR-4.3 晨起/全天对比（v1.2 称「晨峰分析」）：晨起时段（morning）均值与全天均值的差值。**该指标不等同于临床「血压晨峰」**——临床晨峰需要夜间最低血压与晨起后峰值的对比，本 App 无夜间连续监测能力、取不到该值。因此统计页与报告中必须同时展示一行口径说明。

**FR-5 智能分析与提示**
- FR-5.1 录入后即时分级提示：按 3.2-A 诊室血压表给出分级结论与建议文案（**不随「参考口径」设置变化**）。
- FR-5.2 异常预警：单次收缩压 ≥180 或舒张压 ≥110 时，弹出显著警示，建议尽快就医。
- FR-5.3 趋势预警：近 7 天**均值**达到「收缩压 ≥135 **和/或** 舒张压 ≥85」（家庭自测界值）时，在首页顶部显示持续性提示条，低于该值后消失。该阈值**固定取家庭自测界值，不随 FR-7.1「参考口径」变化**——本 App 数据全部为居家自测，若改用诊室阈值（140/90）去判定家庭数据，会系统性漏报。
- FR-5.4 所有提示文案附免责声明："本 App 提示仅供参考，不构成医疗诊断，如有不适请及时就医。"

**FR-6 数据导入导出**
- FR-6.1 导出血压 CSV（UTF-8 带 BOM，Excel 可直接打开），字段：日期、时间、收缩压、舒张压、心率、时段、备注。
- FR-6.2 导出范围可选：全部 / 近 30 天 / 近 90 天。
- FR-6.3 通过系统文件选择器保存到用户指定位置。
- FR-6.4 用药打卡单独导出 CSV：日期、计划时间、药品、剂量、状态、实际打卡时间、备注。
- FR-6.5 导入血压 CSV：格式与 FR-6.1 完全对称（导出文件可直接回导）。经系统文件选择器选取文件 → 解析 → **预览页**显示「有效 N 条 / 重复 N 条 / 错误 N 条」→ 用户确认后入库。
- FR-6.6 导入去重规则：血压记录以「测量时间戳 + 收缩压 + 舒张压」三元组判重，重复行跳过并计数；错误行（缺列、越界、时间格式非法）跳过并在导入结果页逐行列出原因，**不得中断整批导入**。
- FR-6.7 导入用药打卡 CSV：格式与 FR-6.4 对称；按药品名匹配本地档案，无匹配时自动创建药品档案（仅档案，不建计划，状态停用）；打卡记录以「药品名 + 计划时间」判重。
- FR-6.8 导入操作整体在一个数据库事务中执行，任一系统级失败回滚，不产生半批数据。
- FR-6.9 导出**用药计划** CSV：药品、剂量、每日次数、时间点、开始日期、结束日期、备注。与 FR-6.1（血压）、FR-6.4（打卡）共同构成「换机迁移」的完整闭环 —— 仅有血压与打卡时，**药品档案与服药计划无法迁移**，新机上的依从率与今日服药卡片都会是空的。
- FR-6.10 导入**用药计划** CSV：格式与 FR-6.9 对称；判重键为「药品名 + **规范化后**的时间点集合」（库内时间点顺序与文件不同也能正确判重）；导入后立即滚动预生成打卡记录并重建提醒；「每日次数」列与「时间点」实际数量做**交叉校验**，不一致按错误行报告，不静默纠正。
- FR-6.11 导入**其他来源**的 CSV（v1.4 新增）：允许导入其他 App、血压计厂商软件或手写 Excel 导出的文件，**明确不要求**与本 App 的导出格式对称。按「表头同义别名 + 列内容画像」两级信号自动识别每一列的含义（日期 / 时间 / 日期时间 / 收缩压 / 舒张压 / 血压组合值 / 心率 / 时段 / 备注 / 药品 / 剂量 / 状态 / 实际打卡时间 …），**列名与列序可任意、可有多余列**；识别结果在页面上如实展示，并允许用户**手工指定**每一列对应的数据项，改后立即重算预览。容错范围：
  - **日期**：`2026-10-06` / `2026/10/6` / `2026.10.6` / `2026年10月6日` / `20261006` / Excel 序列号 / Unix 秒；缺年份或 2 位年份**不猜**，判为错误行并逐行说明。
  - **时间**：`08:30` / `8:30` / `0830` / `8时30分` / `下午3:20` / `PM 8:30`；日期与时间可**合并在同一列**。
  - **血压**：可写成「收缩压、舒张压」两列，也可写成单列 `128/82`（括号内数值若像心率则识别为心率）。
  - **数值**：容忍全角字符、千分位与单位（`mmHg` / `kPa` / `bpm` / `次/分`）；单位为 kPa 时按 `1 kPa ≈ 7.50062 mmHg` 换算并四舍五入为整数，且在页面上明示已换算。
  - **无时间列**时测量时间统一记为 `00:00` 并在预览页明确提示（**不臆造**时间）。
  - **医学校验与录入完全一致**：数值范围、收缩压 > 舒张压等口径一律复用 `BpValidator`，本路径**不得另立一套阈值**。
  - **判重与入库复用** FR-6.6 / FR-6.8 的既有实现（同一判重键、同一单事务），不新开第二条数据通路。
  - 若识别为**用药计划**列结构，不直接入库，而是提示改用「用药计划」类型（避免把计划当打卡导入）。

**FR-7 设置**
- FR-7.1 参考口径切换（v1.2 称「分级标准」）：诊室血压 140/90 / 家庭自测血压 135/85，**默认家庭自测**（本 App 数据 100% 为居家自测，默认口径与数据场景一致）。
  该项的**唯一作用**是决定图表中哪条参考线以主参考线样式突出显示、以及参考阈值文案的措辞。它**不影响**分级色标、分级名、分级分布统计，也**不影响**趋势预警阈值（FR-5.3 固定 135/85）。
- FR-7.2 数据清空（二次确认 + 输入"确认"防误触，清空范围含血压记录与用药全部数据）。
- FR-7.3 关于页：版本号、免责声明全文。
- FR-7.4 首次启动展示免责声明弹窗（仅一次，读 Preferences 标记；清空数据后重置该标记）。

**FR-8 用药管理**
- FR-8.1 药品档案：药品名称（必填，≤30 字）、单次剂量（文字，如"1 片 / 5mg"）、备注（可选）。支持新增、编辑、停用（归档，历史打卡记录保留不删）。
- FR-8.2 服药计划：每个药品一条生效计划——每日次数（1–4 次）、各次时间点（HH:mm，如 07:30 / 18:00）、开始日期（默认当天）、结束日期（可选，留空为长期）。
- FR-8.3 计划修改或停用**不影响历史打卡记录**（已服 / 跳过 / 漏服永不删除）；修改计划后，当日起按新计划生成提醒。
  同时必须清理**按旧计划预生成、且尚未到期**的 pending 记录。删除边界严格限定为 `status='pending'` **且** `scheduled_time > 当前时间`：过期的 pending 是当时真实存在的服药义务，保留后会自然派生为漏服并计入依从率分母，抹掉反而失真。清理时机为「保存计划 / 停用计划 / 归档药品」三处。
- FR-8.4 同一时间点多个药品合并为一条提醒，避免轰炸。

**FR-9 提醒与打卡**
- FR-9.1 到点系统提醒：使用系统后台代理提醒（reminderAgent），App 未启动/锁屏时也能触发；权限不可用时回退为本地通知（NotificationKit），并在设置页**明示当前提醒方式及其能力边界**（回退模式下提醒只能在应用运行时送达），**不允许静默降级**。
  回退模式下另提供**第三条路径**：进入前台时若当日存在未打卡的漏服项，按自然日去重补发一条通知。这是唯一 100% 可用、不依赖任何系统能力授予的触达方式。技术约束见 4.1。
- FR-9.2 打卡：提醒到达后，可从通知点击进入或直接打开 App，在「今日服药」卡片一键打卡「已服用」或「跳过」。
- FR-9.3 首页顶部显示「今日服药」卡片：列出今日各计划时间点、药品、剂量、状态（待服/已服/跳过/漏服）。
- FR-9.4 漏服判定：超过计划时间 2 小时未打卡自动标记为「漏服」，卡片红色角标提示。
- FR-9.5 依从率统计：统计页展示近 7/30 天服药依从率（已服次数 ÷ 应服次数，跳过与漏服计入应服）。
- FR-9.6 图表联动：趋势图在当日有完整服药打卡的日期下方显示小药丸标记，便于对照服药与血压走势。
- FR-9.7 所有用药相关界面固定显示声明："请严格遵医嘱服药，本 App 不提供用药建议。"

**FR-10 周报 / 月报生成**
- FR-10.1 周期定义：周报=自然周（周一至周日），月报=自然月。入口在统计页顶部「生成报告」，可选择最近 4 周 / 最近 3 个月，也可自定义起止日期（≤92 天）。
- FR-10.2 报告内容板块（按序）：
  1. 头部：周期范围、生成日期、测量次数、服药依从率；
  2. 核心指标卡：平均血压、平均心率、最高/最低、标准差；
  3. 趋势图：周期内每日均值折线图（复用 BpLineChart，含参考线）；
  4. 分级分布：占比条形；
  5. 晨起/全天对比（含一行口径说明，见 FR-4.3）；
  6. 环比对比：本期均值 vs 上一周期均值，差值带升降箭头（无上期数据显示"—"）；
  7. 异常清单：周期内 ≥140/90 的记录列表（日期、数值、时段）；
  8. 用药小结：应服/已服/漏服/跳过次数与依从率；
  9. 底部：免责声明全文。
- FR-10.3 报告输出三方式：**保存长图**（整页渲染为 PNG，用系统安全控件 SaveButton 保存到相册，无需相册权限）、**系统分享**（同一长图走系统分享面板）、**打印/PDF**（调系统打印界面，用户可选"另存为 PDF"）。
- FR-10.4 周期内无血压数据时不生成报告，提示"该周期暂无数据"。

**FR-11 血压图分享**
- FR-11.1 图表页右上角常驻「分享」按钮：将当前视图（含所选周期、曲线、参考线、服药标记）渲染为 PNG 图片。
- FR-11.2 分享图底部自动附加水印行：周期范围 + 生成时间 + "由「血压助手」生成，仅供参考"。
- FR-11.3 分享动作为：生成图片 → 调系统分享面板；同时提供「保存到相册」（SaveButton 安全控件）。
- FR-11.4 图片规格：1080×宽自适应高（约 1080×810），PNG，背景纯白，保证微信查看清晰。

### 2.2 非功能需求（NFR）

| 编号 | 需求 | 指标 |
|---|---|---|
| NFR-1 | 启动性能 | 冷启动到首页可交互 ≤ 1.5s（中端机型） |
| NFR-2 | 录入性能 | 保存一条记录响应 ≤ 200ms |
| NFR-3 | 数据容量 | 支持 ≥5 年数据量（约 4000 条）流畅运行 |

**版本化迁移（`PRAGMA user_version`）**

| 版本 | 内容 |
|---|---|
| v1 | 4 张表 + 4 条普通索引 + `uidx_medlog_med_time` 唯一索引 |
| v2 | 新增 `uidx_bp_triple` 与 `uidx_plan_active_med`，把「导入判重三元组」（FR-6.6）与「每药品一条生效计划」（FR-8.2）从**应用层约定**提升为**结构级约束** |

迁移顺序**必须**是「先清理历史脏数据 → 再建唯一索引」，且整体包在一个事务内。原因：`CREATE UNIQUE INDEX` 在已有脏数据的库上会失败，而该步骤位于**启动初始化路径且没有容错** —— 失败后果不是「索引没建成」，而是**应用直接无法启动**。因此：

1. 清理 `bp_record` 中 `(measure_time, systolic, diastolic)` 重复的记录，保留最早一条（`MIN(id)`）；
2. 同一药品若有多条生效计划，只保留最新一条（`MAX(id)`），其余置为停用而非删除；
3. 建立两条唯一索引；
4. 写入新的 `user_version`。

迁移语句需可**重复执行**（启动时重复调用安全）：清理语句天然幂等，建索引一律带 `IF NOT EXISTS`。

**打卡记录生成规则**：每日首次打开 App 时（或计划变更后），为当天及未来 7 天按生效计划预生成 `pending` 状态的 `med_log` 记录（幂等，已存在则跳过；由 `uidx_medlog_med_time` 唯一索引 + `INSERT OR IGNORE` 双保险）；预生成滚动推进，避免无限预建。

计划修改或停用时，须先清理按旧计划生成、**且尚未到期**的 pending（条件见 FR-8.3）。否则会出现「计划已改、旧提醒与旧卡片仍在」的数据错乱，且这些残留会进入依从率分母，把依从率算低。

**设置存储**：用户偏好（分级标准选择、提醒方式状态等）使用 Preferences（`@kit.ArkData`），不建表。

### 3.2 血压分级标准（核心业务规则）

> **v1.3 重要变更**：本节原定义了两套分级表（诊室 / 家庭自测）并允许用户切换。经核查，**指南只给出了「家庭自测均值 ≥135/85 提示血压偏高」这一条界值，并未给出家庭自测场景下 1/2/3 级的完整分级阈值表** —— v1.2 的「阈值整体下移 5 mmHg」属自创规则，已删除。
> **现在：分级只有一套表（下表 A）；家庭自测界值只作「测量场景界值」使用（B）。**

**A. 诊断分级表（唯一，固定使用）**

依据《中国高血压防治指南（2024 年修订版）》**诊室血压**分类标准：

| 分级 | 收缩压 | 舒张压 | 色标 |
|---|---|---|---|
| 正常 | <120 且 | <80 | 绿 |
| 正常高值 | 120–139 和/或 | 80–89 | 黄 |
| 1 级高血压 | 140–159 和/或 | 90–99 | 橙 |
| 2 级高血压 | 160–179 和/或 | 100–109 | 红 |
| 3 级高血压 | ≥180 和/或 | ≥110 | 深红 |

规则：
- 收缩压与舒张压分属不同级别时，**取较高者**；
- 「和/或」明确含义为：**任一**指标落入该档即判为该档；
- 该表**不随任何设置变化**。列表色标、分级名、分级分布统计、分级提示文案一律以此表为准。

**B. 家庭自测界值（场景阈值，不构成分级表）**

| 用途 | 阈值 |
|---|---|
| 趋势预警（FR-5.3，近 7 天均值） | ≥135 和/或 ≥85 |
| 图表参考线（FR-3.2） | 135/85 |
| 异常清单（FR-10.2 板块 7） | 固定 ≥140/90（见下方例外说明） |

本 App 记录的全部是**家庭自测**数据，故界值取 135/85 而非诊室的 140/90；该界值**固定**，不随 FR-7.1「参考口径」变化。

**C. 设置项「参考口径」（FR-7.1）的边界**

用户可切换「诊室 140/90 / 家庭自测 135/85」，但该项：

- ✅ 决定图表中哪条参考线以**主参考线**样式突出显示、以及参考阈值文案的措辞；
- ❌ **不改变**任何一条记录的分级色标与分级名；
- ❌ **不改变**分级分布统计；
- ❌ **不改变**趋势预警阈值（固定 135/85）。

> **例外：异常清单固定用 140/90** —— 报告是要打印给医生看的，异常清单需要一个稳定、可跨期比较、且与诊室诊断表述一致的界线，因此固定取诊室参考线，不受任何设置影响。

**提示文案模板（录入后即时反馈）**

| 分级 | 文案 |
|---|---|
| 正常 | 本次血压正常，请保持规律监测。 |
| 正常高值 | 本次血压处于正常高值，建议注意低盐饮食与规律作息，持续观察。 |
| 1 级 | 本次血压偏高（1 级范围），建议连续监测 7 天，如持续偏高请咨询医生。 |

|---|---|
| 05:00–09:00 | 晨起 morning |
| 09:00–14:00 | 上午/午间 forenoon |

### 3.4 服药打卡状态机

```
pending（待服）
  ├─ 用户在 计划时间±任意时刻 点「已服用」→ taken（已服），记录 taken_time
  ├─ 用户点「跳过」→ skipped（跳过）
  └─ 当前时间 > 计划时间+2h 且仍 pending → missed（漏服，系统自动标记）
```

- `missed`/`skipped` 后可补打卡为 `taken`（保留原状态变更痕迹：taken_time 晚于 scheduled_time+2h 的 taken 在统计中仍计为已服，但 UI 标注「补记」）。
- 依从率 = 已服次数 ÷ 应服次数。**应服 = taken + skipped + missed + pendingNotDue**（即该周期内按计划产生的全部服药义务，含已预生成但尚未到期的 pending）；应服为 0 时返回 `null`，UI 显示「—」。
- 状态判定为纯函数，放 `MedService`，单测覆盖全部迁移路径。
- **`missed` 是「读时派生」状态**：任何时刻由 `resolveStatus(记录, 当前时间)` 按「超时 2h」规则算出，落库与否不影响正确性；前台只做一次机会性落库（`markMissed`），**不引入 `workScheduler`、后台定时任务或额外耗电**。所有统计口径一律以派生结果为准。

3. **数据库单例**：`BpDatabase` 全局单例，App 启动时初始化并执行建表/迁移。
4. **版本化迁移**：建表语句带 `PRAGMA user_version`，后续变更走 `onUpgrade` 迁移函数。

## 6. 开发阶段规划（里程碑）

> 每个阶段 = 一次独立可验收的交付。agent 完成一个阶段后必须输出「阶段自检报告」（对照第 7 章对应清单逐项打勾），未通过不得进入下一阶段。
>
> **百分比口径**：下列百分比是**相对工作量权重**，合计恰为 100%（v1.2 的 5+20+20+15+20+25+10 = 115%，已在本版配平）。

### M0：工程脚手架（预计工作量 5%）
- 创建 DevEco 工程（API 12，stage 模型，EntryAbility）。
- 按 4.2 建立目录结构与空文件骨架。
- `BpDatabase` 完成建表与初始化，启动可跑通空首页。
- **出口条件**：工程编译通过，真机/模拟器可启动，首页显示空列表占位。

### M1：数据层与录入（18%）
- `BpDatabase` 全部四张表的 CRUD（含事务、索引）。
- RecordEditPage 录入/编辑/删除，含全部校验规则。
- 首页列表 + 分级色标 + 分页加载。
- **出口条件**：清单 CL-1、CL-2 全部通过。

### M2：图表与统计（18%）
- `BpLineChart` Canvas 组件（三曲线 + 参考线 + 点击浮层 + 服药标记 + 空态）。
- `StatsService` 全部统计指标。
- ChartPage、StatsPage 页面。
- **出口条件**：清单 CL-3、CL-4 全部通过。

### M3：智能分析与设置（12%）
- `GradeService` 分级判定（固定诊室表）+ 提示弹窗 + 3 级强警示。
- 首页趋势预警条（FR-5.3）。
- CSV 导出（血压，Picker 保存）。
- 设置页全部功能。
- **出口条件**：清单 CL-5、CL-6 全部通过。
- **v1.3 顺序修正**：v1.2 把「用药打卡 CSV 导出」放在本阶段，但 `med_log` 的写入方在 M4 —— 依赖倒置。已将**用药打卡导出与用药计划导出/导入统一移入 M5**（与报告、导入同批交付）。

### M4：用药管理与提醒打卡（20%）
- **第一步（阻塞项）**：真机验证 `ohos.permission.PUBLISH_AGENT_REMINDER` 对调试签名应用的可用性，确定主用 reminderAgent 还是回退 NotificationKit，结论写入自检报告。
  （预期：该权限为 **normal 级 / system_grant**，安装即授予，因此**不影响打包与安装**；需要实测的是**代理提醒功能**是否可用 —— 设备支持则设置页显示「代理提醒」，设备有运行时管控则显示「本地通知」并走回退。两种情况都需记录。详见《运行与部署说明》第 6 节。）
- MedPage、MedPlanEditPage 全部 CRUD 与校验。
- `MedService`：打卡状态机、依从率、每日预生成逻辑。
- `ReminderService`：提醒调度（新增/修改/停用计划时同步重建提醒；同时间点合并）。
- 首页 TodayMedCard + 打卡弹窗 + 漏服自动标记 + 图表服药标记 + 统计页依从率。
- **出口条件**：清单 CL-8 全部通过。

### M5：报告、导入导出与分享（20%）
- `ReportService` 报告数据组装 + ReportPage 九个板块（FR-10.2）。

- **导出**：血压 CSV（FR-6.1–6.3）、用药打卡 CSV（FR-6.4）、**用药计划 CSV（FR-6.9）**。
- **导入**：血压 CSV（FR-6.5）、用药打卡 CSV（FR-6.7）、**用药计划 CSV（FR-6.10）**、**其他来源 CSV（FR-6.11，v1.4 新增：列自动识别 + 容错解析 + 手工列映射）**；含解析（引号转义兼容）、判重、预览页、事务导入、结果页。
- 设置页导入入口。
- **出口条件**：清单 CL-9、CL-10 全部通过。

### M6：打磨与验收（7%）

- **出口条件**：第 7 章全部清单通过，产出最终交付包。

## 8. 签名与部署流程（真机安装）

> 单机自用场景使用**自动化调试签名**，无需上架流程。按可上架标准预留正式签名能力。

### 8.1 环境准备
1. 安装 DevEco Studio 5.0+（含 HarmonyOS NEXT SDK, API 12）。
2. 登录华为开发者账号（免费注册即可，实名认证后支持自动化签名）。
3. 手机开启「开发者模式」：设置 → 关于手机 → 连续点击版本号 7 次；再进入 设置 → 系统与更新 → 开发人员选项 → 开启 USB 调试。

### 8.2 自动化签名与安装
1. DevEco Studio → File → Project Structure → Signing Configs → 勾选「Automatically generate signature」，登录账号后自动生成调试证书与 Profile。
2. USB 连接手机，设备管理器中选中真机。
3. 点击 Run（或 `hvigor assembleHap` 后用 `hdc install entry-default-signed.hap`）。
4. 手机首次运行需在弹窗中信任开发者证书。

### 8.3 注意
- 调试证书有效期约 1 年，到期在 DevEco 中重新自动生成即可，App 数据不受影响。
- 若更换手机，新手机重新签名安装，旧数据不迁移（单机版接受此限制）。**迁移路径**：旧机导出「血压 / 用药打卡 / 用药计划」三份 CSV → 新机用「导入数据」逐份导入（见 FR-6.5–6.10）。
- 未来若决定上架：补充正式签名证书、隐私政策页、应用图标全套规格，走 AppGallery Connect 提审。代码层面因 NFR-5 已最小权限，无需大改。

## 9. 给执行 agent 的协作约定

1. **严格按里程碑推进**：M0→M6，每阶段结束输出自检报告，对照第 7 章逐项打勾，列出未通过项与原因。
2. **不得变更已定决策**：技术栈（4.1）、数据模型（3.1）、分级标准（3.2）、页面结构（第 5 章）为锁定项；发现冲突时停下来报告，等待裁决，不得自行改设计。
   **补则**：若锁定项本身存在事实错误或内部冲突（例如权限名不存在、两套分级表互相矛盾、打印路径与出图路径冲突），应**先提交可复现的证据再提请修订**，不得静默绕过，也不得为了"符合文档"而写出已知错误的实现。
3. **可自由决策的范围**：具体组件内部实现、动画细节、图标素材（用系统图标或纯色占位均可，风格扁平简洁）。
4. **每阶段交付物**：可编译运行的完整工程源码 + 自检报告 + 变更说明（相对上一阶段改了哪些文件、为什么）。
5. **遇到需求未覆盖的情况**（如某交互细节未定义）：按「最少惊讶原则」选最朴素的实现，并在自检报告中标注为「待确认项」，不要静默发挥。
6. **测试数据**：M6 性能验证使用脚本生成的模拟数据——4000 条血压记录（收缩压 105–165 正态分布，覆盖全时段、含备注）+ 2 个药品 1 年打卡记录（约 1100 条，含漏服/跳过/补记混合状态）+ **用药计划 CSV（2 个药品）** + 一份 4000 行导入测试 CSV（含故意构造的重复行与错误行），验证完成后提供一键清空。生成器需确定性（固定随机种子），保证结果可复现。
7. **提醒权限红线**：v1.2 写的 `ohos.permission.REMINDER_AGENT` **并不存在**，正确名称是 `ohos.permission.PUBLISH_AGENT_REMINDER`。
   该权限为 **normal 级 / system_grant**，声明后安装即授予，**不阻塞编译与安装、也不要求手动签名**；但**代理提醒功能**的可用性因设备 / ROM 而异（部分设备有运行时管控，`publishReminder` 返回 `1700001`）。
   因此：两条路径都必须实现 + 运行时探测自动回退 + 设置页明示当前方式；**可用性结论必须在自检报告中给出实测证据（V1）**。
   不得在未验证的情况下先写页面再返工，**也不得把"尚未验证"写成"必然不可用"**。

## 10. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| agent 对 HarmonyOS NEXT API 不熟，使用过时 API（如 API 9 的 FA 模型） | 编译失败/审核拒 | M0 出口条件强制验证 API 12 stage 模型可编译 |
| Canvas 自绘图表质量不可控 | 图表粗糙 | 5.3 已给绘制规格；M2 自检含截图比对 |
| 分级医学表述错误 | 误导用户 | 分级只用 3.2-A 诊室表（**已删除无出处的"家庭自测分级表"**）；CL-5 边界值用例强制核对；文案锁死在资源文件 |
| 临床术语误导（"晨峰"） | 报告打印给医生看时造成误读 | 已更名「晨起/全天对比」并在统计页与报告页固定展示口径说明（FR-4.3） |
| 健康类应用上架需资质与更严隐私审查 | 上架受阻 | 本期仅真机自用、不上架；NFR-5 已按最小权限设计。未来若上架需补充资质材料、隐私政策页与全套图标规格 |
| v1→v2 迁移在含脏数据的旧库上失败 | **应用无法启动**（非"约束没建成"） | 迁移严格按「先清理 → 后建索引 → 单事务」执行，建索引一律带 `IF NOT EXISTS` 保证可重复执行；`tools/sqlcheck.mjs` 用真实 SQLite 执行迁移，并含「不清理直接建索引必定失败」的反证用例 |
| 调试签名过期导致 App 无法打开 | 数据不可访问 | 8.3 已说明重新签名流程；数据在应用沙箱内，重装同包名同签名不丢 |
| 误触清空数据 | 数据丢失 | FR-7.2 输入"确认"防误触 + 导出先行建议 |
| 代理提醒在部分设备上受运行时管控，`publishReminder` 返回 `1700001` | 系统级到点提醒失效 | 两条路径同时实现，运行时探测后自动回退本地通知；回退模式下另加「进入前台按自然日补发漏服通知」兜底；设置页明示能力边界。可用性需真机实测（V1） |
| 系统省电策略杀死后台导致通知延迟 | 提醒不准时 | 设置页引导用户将 App 加入"受保护应用"/关闭电池优化；CL-8 要求息屏实测 |
| 计划修改导致提醒与打卡记录错乱 | 数据不一致 | 打卡记录存快照（med_name/dosage），与计划解耦；预生成幂等规则见 3.1 |
| componentSnapshot 对长滚动页出图截断 | 报告长图不完整 | 报告用离屏容器按内容高度一次性渲染，CL-9 验证完整性；M5 自检附截图 |
| 系统打印界面不支持"另存为 PDF"（机型差异） | PDF 路径失效 | 长图为保底输出，报告三输出方式中长图与分享不依赖打印；真机实测写入 M5 自检报告 |
| 导入脏数据（手工编辑过的 CSV）导致解析崩溃 | 数据损坏/闪退 | 解析层全量 try-catch 按行隔离，错误行只跳过不入库；CL-10 幂等与回滚用例强制验证 |

## 附录 A：CSV 导出格式示例

**血压记录**

```csv
日期,时间,收缩压(mmHg),舒张压(mmHg),心率(bpm),时段,备注
2026-10-06,08:12,128,82,72,晨起,服药后
2026-10-05,21:40,135,88,76,睡前,
```

**用药打卡记录**

```csv
日期,计划时间,药品,剂量,状态,实际打卡时间,备注
2026-10-06,07:30,缬沙坦,1片/80mg,已服用,07:42,
2026-10-05,18:00,缬沙坦,1片/80mg,漏服,,
2026-10-05,12:00,二甲双胍,1片/0.5g,已服用(补记),21:10,聚餐后补服
```

**用药计划（v1.3 新增，FR-6.9）**

```csv
药品,剂量,每日次数,时间点,开始日期,结束日期,备注
缬沙坦,1片/80mg,2,07:30 / 18:00,2026-01-01,,
二甲双胍,1片/0.5g,1,12:00,2026-03-01,2026-12-31,
```

- 「时间点」列用分隔符连接多个 HH:mm；「每日次数」须与实际时间点数量一致，否则该行按错误行报告。
- 判重键为「药品名 + 规范化后的时间点集合」，与库内时间点的排列顺序无关。
- 「状态」列还支持补充值「待服」（附录 A 未列出，但未到期的 pending 记录也必须能导出并原样回导，否则「导出→导入」会丢数据、破坏 CL-10 的往返幂等性）。
