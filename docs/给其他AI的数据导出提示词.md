# 给其他 AI 的血压数据导出提示词

> 用途：你的血压数据在另一个 AI 手上，用它把数据整理成**这个 App 能导入的 CSV**。
>
> 本文里的每一条格式口径都**在本机实测过**（见文末「这些口径是怎么验证的」），
> 不是照文档抄的。两段提示词都可**整段复制**发给对方。

---

## 用法

1. 优先用 **提示词 A（精确格式）**：它产出的是本 App 的规范格式，导入时选「**血压记录**」，
   走的是严格路径 —— 判重、校验、往返一致性都有测试覆盖。
2. 如果对方说数据里没有时间、或者列结构改不动，就用 **提示词 B（宽松格式）**：
   导入时选「**其他来源**」，该模式能自动识别列名与日期写法。
3. 拿到文件后，**先在电脑上预检**再传到手机（见下文第 4 节）—— 有问题当场就能发现。

---

## 提示词 A：精确格式（推荐，导入时选「血压记录」）

把下面整段（含代码块）复制给对方：

````text
我需要你把我的血压数据整理成一个 CSV 文件，供一个血压记录 App 导入。
请严格按下面的格式输出，不要添加额外说明，也不要用 Markdown 表格代替文件。

【文件要求】
- 文件名：bp_export.csv
- 编码：UTF-8，并且**带 BOM**（若你只能输出纯文本，请在回复里说明这一点）
- 分隔符：英文逗号 , ；换行：\r\n
- 首行是表头，必须**逐字**是下面这一行（括号是英文半角，不要翻译、不要改单位）：
日期,时间,收缩压(mmHg),舒张压(mmHg),心率(bpm),时段,备注
- 表头之后每行一条记录。不要有空行、小计行、合计行、说明行，不要加序号列
- 字段内如果出现逗号、双引号或换行，用英文双引号把该字段整体包起来，
  字段内的双引号写成两个双引号（RFC 4180）。
  ⚠️ 这条必须遵守：不转义的双引号会被解析时吞掉，等于改动了我的数据。

【各列口径】
1. 日期：必填，格式 YYYY-MM-DD，月与日补零，例如 2026-10-05
2. 时间：必填，24 小时制 HH:mm，小时与分钟补零，例如 07:05、21:40
3. 收缩压(mmHg)：必填，整数，40–300
4. 舒张压(mmHg)：必填，整数，30–200，并且**必须小于收缩压**
5. 心率(bpm)：选填，整数 30–220。没有就**留空**（写成两个逗号相邻），
   不要写 0、-、null、N/A、未知
6. 时段：选填，只能是这五个词之一：晨起 / 上午 / 下午 / 睡前 / 其他。
   **不确定就留空**（留空没问题，App 会根据时间自动推断）。
   注意：写其它词（例如"清晨""早上"）不会报错，但会被忽略并改按时间推断，
   所以宁可直接留空。
7. 备注：选填，App 内录入限制 100 字以内，请控制在这个长度内。没有就留空。

【必须避免的写法】（这些行会被判为错误行、整行跳过不入库）
- 日期写成 2026/10/5、2026年10月5日、2026.10.5 或 Excel 日期序列号（如 46295）
- 时间写成 7:5、7点05分、07:05:00 之外的写法
- 收缩压/舒张压带小数（132.0）或带单位（132mmHg、17.2kPa）
- 把收缩压和舒张压两列写反（结果会出现"收缩压 ≤ 舒张压"）
- 数值超出上面范围
- 心率位置写了 0 或 N/A

【数据完整性要求（重要）】
- 不要为了通过上面的校验而修改我的原始数值：不要四舍五入、不要截断、不要补 0、不要估算缺失的心率。
- 如果原始数据里确实存在"收缩压 ≤ 舒张压"或超出范围的行，请**保持原值不变**，
  并在回复里单独列出来告诉我行号与数值，由我决定怎么处理。
- 原文是 kPa 的请先告诉我，不要自己换算，我会改用另一种导入方式。

【交付前请自检，并在回复里报告】
1. 数据行数（表头以外的行数）
2. 最早和最晚的测量日期
3. 有几行是"收缩压 ≤ 舒张压"（应为 0 行）
4. 时间列有没有缺失值（应为 0 个）
5. 一共有几行的心率为空

【格式示例（前 3 行，请照此输出）】
日期,时间,收缩压(mmHg),舒张压(mmHg),心率(bpm),时段,备注
2026-10-01,06:35,132,86,74,晨起,
2026-10-01,12:10,128,82,,,
2026-10-01,21:40,138,88,76,睡前,服药后
注意第 2 行：没有心率就留空（128,82,,），时段也不填。
````

## 提示词 B：宽松格式（当对方改不动数据结构时用，导入时选「其他来源」）

适用情形：数据只在某个系统里、导出来就是别的列名；或者**没有时间字段**；
或者数值是 kPa 单位。把下面整段复制给对方：

````text
我需要你把我的血压数据导成一个 CSV 文件，供一个血压记录 App 导入。
这个 App 有一个"其他来源"导入模式，能自动识别列名与日期写法，
所以列名叫什么、列的顺序、有没有多余列都不重要。你只需满足下面这些最低要求：

【硬性要求】
1. 第一行是表头（中文或英文都行），列名能让人类看出含义即可，
   例如：测量日期、测量时间、高压、低压、脉搏、备注
   （也可以用：日期、时间、收缩压、舒张压、心率）
2. 日期写成年-月-日的形式，优先 YYYY-MM-DD（如 2026-10-05）；
   用 2026/10/5、2026年10月5日 也可以，但**不要**用 Excel 日期序列号
3. 血压要能看出哪列是收缩压（高压）、哪列是舒张压（低压），且收缩压 > 舒张压
4. 时间列写成 HH:mm（如 07:30）；若原文里根本没有时间，**跳过时间列即可**，
   但请在回复里明确告诉我"没有时间字段"
5. 数值必须是数字：不要带 mmHg/kPa 单位混在单元格里，不要用"正常/偏高"这类文字
6. 一行一条记录；不要小计/合计行、不要空行、不要合并单元格

【可选，有就给】
- 心率/脉搏列：没有就整列不要
- 备注列：有就保留
- 时段列：留空即可，App 会按时间推断

【数据完整性要求（重要）】
- 不要修改原始数值：不要四舍五入、不要换算单位、不要估算缺失的心率。
- 若原始数据是 kPa（数值在 10–35 之间），请**保持原值**并告诉我单位是 kPa，
  不要自己换算（App 能按 kPa 识别并换算）。
- 若存在"收缩压 ≤ 舒张压"或明显异常（如 300 以上）的行，保持原值并单独列出告诉我。

【交付前请报告】
1. 数据行数（表头以外）
2. 最早与最晚日期
3. 列名清单（中文列名 + 你认为它对应什么）
4. 单位是 mmHg 还是 kPa
5. 有没有时间字段
6. 有几行血压数值异常，逐行列出行号与数值

【示例（示意即可，列名可不同）】
测量日期,测量时间,高压,低压,脉搏,备注
2026-10-01,6:30,132,86,74,起床后
2026-10-02,12:10,128,82,,
````

## 4. 拿到文件后：先在电脑上预检

不用先传到手机 —— 在本机跑一次就能知道能不能导入、哪些行会被跳过：

```bash
node tools/check-import-file.mjs <对方给你的 csv 路径>
```

它会做三件事：

1. 报出**严格格式**三种类型（血压记录 / 用药打卡 / 用药计划）各自的有效行数；
2. 报出**其他来源**模式的自动列识别结果（哪一列被认成什么）与有效行数；
3. 给出结论：**能不能导入、导入时该选哪个类型**，并把出错行的行号与原值列出来。

退出码：`0` = 无错误行可直接导入；`1` = 有错误行或无法导入。

> 该工具直接调用工程里**真实的解析实现**（不是另写一份规则），
> 词表从 `resources/base/element/string.json` 读取，所以结论与 App 内行为一致。

然后传到手机，在 App 里：**导入数据 → 选对应类型（或「其他来源」）→ 选文件 →
核对「有效 / 重复 / 错误」与「前 5 行预览」→ 确认导入**。

## 5. 附：如果还有用药数据（可选）

同一个导入页还支持两类药物数据。若对方手里有，可以一并要过来：

- **用药打卡**（导入时选「用药打卡」），表头逐字：
  `日期,计划时间,药品,剂量,状态,实际打卡时间,备注`
  - 日期 `YYYY-MM-DD`、计划时间 `HH:mm`
  - 状态只能是：`已服用` / `已服用(补记)` / `跳过` / `漏服` / `待服`
    （外部写法如"已服""吃过""漏服"也能被「其他来源」识别）
  - 实际打卡时间 `HH:mm`（补记的那次填真实打卡时刻），没有就留空
- **用药计划**（导入时选「用药计划」），表头逐字：
  `药品,剂量,每日次数,时间点,开始日期,结束日期,备注`
  - 时间点列用分号分隔多个时刻，如 `07:30;18:00`
  - 「每日次数」必须与时间点的实际个数一致（不一致会被判为错误行）
  - 结束日期可留空（表示长期）

## 6. 这些口径是怎么验证的

本文档里的格式要求不是从设计文档里抄的，而是拿真实解析实现跑出来的，实测结论：

| 验证项 | 结果 |
|---|---|
| 文中的示例（3 行） | 严格路径 **有效 3 / 错误 0** |
| 示例中时段留空的那行 | 按时间推断为「上午」（12:10）✓ |
| 14 种「必须避免的写法」 | 逐条实测**全部被判为错误行**（含斜杠日期、中文日期、Excel 序列号、未补零时间、中文时间、带小数、带单位、两列写反、各类超范围、心率写 0 / N/A、时间缺失） |
| 边界值 40/30、300/200、心率 30 与 220 | 全部**被接受**（范围是闭区间） |
| 备注含逗号并用双引号包裹 | 正确回读，未被截断 |
| 备注里写**未转义**的裸双引号 | 引号被**静默吞掉** → 所以提示词里把 RFC 4180 转义列为硬要求 |
| 时段写非枚举词（"清晨""早上"） | **不报错**，被忽略并按时间推断 → 所以提示词里写"宁可直接留空" |
| 备注超过 100 字 | 导入**不被拒绝**（100 字是应用内录入的限制）→ 所以写"请控制"而非"会报错" |

最后两条是**与直觉不符**的，已在提示词里按实际行为表述，避免给对方的约束是错的。

复现方式（本机可跑）：

```bash
node tools/check-import-file.mjs <任意 csv>     # 用真实解析实现预检
node tools/parity/run.mjs                       # 526 条断言，含导入解析与判重
```
